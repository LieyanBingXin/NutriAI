## Slide 2 · 总览：一条主线「信息标签化」

```
这一周我们回答一个问题：
  用户的信息（喜好、忌口、冰箱、身体状态、角色偏好）散落在各处，
  AI 怎么才能一次读全、准确回应？

  ┌────────────────────────────────────────────┐
  │  散落 → 统一 → 可管理 → 可引用              │
  │                                            │
  │  信息标签化：把每一条信息抽象成「标签」，     │
  │  集中放在看板上，一眼看全、随时引用。        │
  └────────────────────────────────────────────┘

四个支撑点：
  ① AI 对话助手 —— 18 种规则意图 + AI 兜底，规则优先、AI 兜底，能直接执行操作
  ② 本地 RAG —— 权威食物库 + 膳食指南，让 AI 有据可依、不编造营养数值
  ③ 便利贴看板 —— 七大类信息分区，AI 自动读全 + 对话中引用提及
  ④ 稳健性修复 —— 意图 / 落库 / 打包 / 测试全面加固

一句话：不做堆料，做"把信息盘活"这件事。
```

## Slide 3 · 核心概念：什么是「信息标签化」

```
痛点：信息是散着的，AI 是"瞎"的

  传统做法                         我们的做法
  ┌─────────────────────────┐     ┌──────────────────────────┐
  │ 喜好 → 藏在画像表单里    │     │ 喜好 → 💚 标签（统一管理）│
  │ 忌口 → 记在备注里        │     │ 忌口 → 🚫 标签（自动避开）│
  │ 冰箱 → 用户自己心里记着  │     │ 冰箱 → 🧊 标签（有料推荐）│
  │ 身体状态 → 问一次说一次  │     │ 状态 → 🩺 标签（据此调整）│
  │ AI 角色 → 每次重新设定   │     │ 角色 → 🎭 标签（注入提示）│
  └─────────────────────────┘     └──────────────────────────┘

  七类信息，七种标签，一个看板
  🧬 基础信息  🩺 身体状态  💚 喜欢吃  🚫 不喜欢/过敏
  🧊 冰箱里有  🎭 AI 角色  🤖 AI 营养提醒（系统自动算）

  两条机制要分清：
  · 自动上下文：AI 每轮对话都自动读全这些标签
    （不勾选、不拖动，信息照样带进对话）
  · 引用提及：把标签拖到「便利贴」再点击，只是让 AI
    在当前这轮"重点回应该标签"，不是信息送达的唯一途径

  核心价值：
  · 用户只需"打标签"，不用反复解释自己是谁
  · AI 每次对话都自动带完整上下文，回复更精准
```

## Slide 4 · AI 助手：18 种规则意图 + AI 兜底

```
设计原则：能规则解析的，绝不浪费一次 AI 调用

  📋 查询类（6 种，只读，直接返回数据）
     今日汇总「今天吃了多少」 本周汇总「这周数据」 查体重「现在多重」
     冰箱查询「冰箱有什么」 营养缺口「缺什么」 今日进度「还能吃多少」

  ✍️ 写入类（8 种，自动提取 + 直接执行）
     记录体重「今天 68kg」 记录饮食「早餐吃了鸡蛋+牛奶」
     冰箱添加「我家有鸡胸肉」 清空冰箱「清空冰箱」 移除食材「吃完了鸡蛋」
     撤销上一条「刚才记错了」 偏好「喜欢番茄/讨厌香菜」 更新画像「我要减脂」

  🎯 生成 / 行动类（4 种）
     推荐食谱「今晚吃什么」 换一批「再推荐一个」
     一周食谱规划「给我一周菜单」 帮助「你能做什么」

  🤖 AI 兜底（1 种）
     以上都不匹配 → 拼装完整上下文（画像 + 偏好 + 冰箱 + 今日数据）→ 流式返回

  关键设计：
  · 规则命中 → 即时完成，零 API 成本
  · 规则未命中 → 带真实上下文发 AI，不瞎编
  · 写操作返回确认卡，避免 AI 误操作用户数据
```

## Slide 5 · AI 助手：三层处理流水线

```
用户说："今天吃了 200g 牛肉，刚称 68kg"

  Layer 0 —— 预加载真实数据
  ┌──────────────────────────────────────┐
  │ 今日饮食 + 用户画像 + 冰箱快照        │
  │ → 后续 AI 兜底时用的是真数据，不瞎编  │
  └──────────────────┬───────────────────┘
                     ▼
  Layer 1 —— 查类意图（只读，优先级最高）
  ┌──────────────────────────────────────┐
  │ "查一下 / 今天吃了 / 这周 / 缺什么"   │
  │ → 命中则直接返回汇总结果               │
  └──────────────────┬───────────────────┘
                     │ 未命中
                     ▼
  Layer 2 —— 写类意图（自动提取 + 执行）
  ┌──────────────────────────────────────┐
  │ 体重三层正则 → "刚称 68kg" ✓          │
  │ 食材切分    → "鸡蛋、牛奶"            │
  │ 偏好识别    → "喜欢 / 讨厌"           │
  │ → 调对应 Service 写入数据库           │
  └──────────────────┬───────────────────┘
                     │ 未命中
                     ▼
  Layer 3 —— 分析 + AI 兜底
  ┌──────────────────────────────────────┐
  │ "缺什么" → 营养缺口分析               │
  │ "推荐"   → 生成食谱                   │
  │ 其余     → 完整上下文发 AI，流式返回   │
  └──────────────────────────────────────┘
```

## Slide 6 · 本地 RAG：让 AI 不再"编营养数据"

```
设计动机：大模型背不出每 100g 鸡胸肉多少卡，硬答就会编。
方案：内置本地知识库，检索后注入 prompt，让 AI 照着权威数据说。

  两个知识库（启动时加载，无向量数据库）
  ┌──────────────────────────────────────────────┐
  │ rag/food_nutrition.json                       │
  │   50 种常见食物（主食 / 肉蛋 / 蔬菜 / 乳制品…）│
  │   每条：名称 + 别名 + 每 100g 营养             │
  │   { 热量 / 蛋白 / 碳水 / 脂肪 / 纤维 }         │
  ├──────────────────────────────────────────────┤
  │ rag/dietary_guidelines.json                   │
  │   12 条《中国居民膳食指南（2022）》            │
  │   每条：分类 + 标题 + 权威建议原文             │
  └──────────────────────────────────────────────┘

  检索（轻量 TF-IDF，不依赖向量库）
  · 中文分词：按 \p{L}\p{N} 切词 + 字符 bigram
  · 打分：查询词命中率（命中词数 / 查询词数）
  · Top-K：指南取 3 条、食物取 5 条

  注入（Augmentation）
  · "=== Food Nutrition Data (authoritative, do not fabricate) ==="
  · "=== Dietary Guidelines (cite source when referencing) ==="
  · 拼进 prompt，明确要求"不得编造、引用来源"
```

## Slide 7 · RAG 落地：本地先算，算不出再问 AI

```
三个使用场景，共同目标：能本地搞定的，绝不调 AI

  ① 食物识别（本地优先）
     "200g 牛肉" → 正则抓「数量+单位」→ 单位换算成克
     → 查食物库命中 → 按 100g 比例算营养 → source=local-db
     只有本地 miss，才 fallback 到 AI 识别

  ② 营养缺口解读
     用户近 7 天达标数据 → 注入膳食指南
     → AI 引用权威建议，给出 2-4 条可执行调整

  ③ AI 教练反馈
     画像 + 今日/近期数据 → 注入权威食物数据
     → 生成 3-5 条行动建议，优先参考权威数据

  单位换算表（tryLocalRecognize）
     kg / 公斤 = 1000g   斤 = 500g   两 = 50g   个 / 只 = 100g
     份 = 200g   碗 = 250g   盘 = 300g   杯 = 250g   勺 = 10g

  价值：
  · 防幻觉 —— 权威数据写死在库，AI 不编数值
  · 省成本 —— 常见食物本地秒算，零 API 调用
  · 有依据 —— 建议可回溯到膳食指南来源
```

## Slide 8 · 便利贴看板：七大类信息分区

```
一个页面，看全你的"营养画像"，每一条都是可交互的标签

  ┌────────────────────────────────────────────────┐
  │ 🧬 基础信息   性别·年龄·身高体重·目标·地区      │
  │               纯展示，点「编辑」跳画像页        │
  ├────────────────────────────────────────────────┤
  │ 🩺 身体状态   [+ 高血压 / 乳糖不耐受 …]        │
  │               疾病身体状况，AI 据此调整建议     │
  ├────────────────────────────────────────────────┤
  │ 💚 喜欢吃     [+ 番茄 / 三文鱼 …]              │
  │               推荐时优先                       │
  │ 🚫 不喜欢     [+ 香菜 / 花生 …]                │
  │               过敏 / 忌口，AI 自动避开          │
  ├────────────────────────────────────────────────┤
  │ 🧊 冰箱里有   [+ 鸡胸肉 / 西兰花 …]            │
  │               现有食材 → 触发"有料推荐"        │
  ├────────────────────────────────────────────────┤
  │ 🎭 AI 角色设定 [+ 温柔女友风 / 古风 …]         │
  │               注入 AI System Prompt，改语气    │
  ├────────────────────────────────────────────────┤
  │ 🤖 AI 营养提醒  （系统自动计算）        │
  │               近 7 天营养缺口 + AI 洞察        │
  └────────────────────────────────────────────────┘

数据来源分离：
  · 用户手动维护的标签 → 存数据库（喜好 / 忌口 / 冰箱 / 角色 / 身体状态）
  · 系统自动算的标签 → 后端 gap 字段实时计算（营养提醒）
  · 只读摘要 → 基础信息（画像硬数据）
```

## Slide 9 · 便利贴：在对话中「引用提及」标签

```
设计动机：这些标签 AI 本来都读得到，为什么还要拖到便利贴？
答案：为了"这轮我想重点聊这个"，而不是再口头描述一遍

  正确的关系（关键）
  ┌────────────────────────────────────────────────┐
  │  看板标签 = 信息本体（AI 始终读得到，无需勾选） │
  │  便利贴   = 对话引用（这轮想重点提哪些标签）    │
  │                                                │
  │   💚 番茄（看板）  ──拖拽──▶  📌 番茄（便利贴） │
  │        ↑                          ↓            │
  │   AI 本来就读得到             点击 → 在对话里     │
  │   （不拖动也在）               "提及" 这个标签   │
  └────────────────────────────────────────────────┘

  便利贴的价值：不是"喂信息"，是"点名"
  · 想聊冰箱里的鸡胸肉 → 拖到便利贴 → 点击 → AI 围绕它回应
  · 「全部挂到对话」→ 把这一批标签一次性塞进当前这条消息
  · 手写自定义标签（"＋ 写一个便利贴…"）→ 临时补一句
  · 本地持久化：localStorage nutriai_rail_picks_v2
    { likes / dislikes / fridge / gap / custom }
```

## Slide 10 · AI 营养提醒：系统自动计算的标签

```
为什么它是"特殊的标签"？因为不用用户动手，AI 自己算

  来源     其他分区：用户手动添加           营养提醒：系统自动计算
  数据     喜好 / 忌口 / 冰箱 / 角色        营养缺口（近 7 天饮食分析）
  交互     点击标签 → 发给 AI              纯展示，不可点击
  样式     实线边框 + 纯色                 虚线边框 + 紫粉渐变 + 顶部渐变条

  ┌─ 顶部渐变条（紫 → 粉）───────────────────┐
  │  🤖 AI 营养提醒                          │
  │  📊 近 7 天：12 餐记录                    │
  │  热量    ████████████░░  60%  偏低       │
  │  蛋白质  ████████████░░  80%  正常       │
  │  膳食纤维 ██░░░░░░░░░░░░  20%  严重不足  │
  │  ┌─ 💡 AI 洞察 ─────────────────────┐   │
  │  │ 蔬菜摄入明显偏少，建议中午加一份   │   │
  │  │ 深色蔬菜，晚餐用杂粮替代白米饭    │   │
  │  └───────────────────────────────────┘   │
  └──────────────────────────────────────────┘

  缺口分级：严重不足 < 40%（红）→ 偏低 < 80%（橙）→ 正常 < 110%（绿）
```

## Slide 11 · 稳健性修复

```
这一周不堆新功能，把已有的打磨到"不会翻车"

  ① 序数指代餐别不再写死
     问题："就选第一个吧"，餐别硬编码"午餐"，跨时段会记错
     修复：mealTypeForHour(int hour) 按时段推断
           5-10 早餐 / 10-14 午餐 / 14-17 加餐 / 17-22 晚餐 / 其余 加餐
           序数指代直接映射前端 suggestedRecipes，绕过 AI 食物识别

  ② 落库空值兜底
     问题：新增日记 amountGram 传 null 会原样入库
     修复：新增分支 null → 0.0；更新分支保留显式清空语义

  ③ 核心逻辑回归测试
     AssistantIntentServiceTest 由 31 条 → 34 条
     新增：序号解析 / 序号守卫 / 时段餐别映射
     mvn test 34/34 全部通过

  ④ Fat JAR 打包修复
     问题：spring-boot-maven-plugin 缺 executions，package 产出瘦 jar
     修复：绑定 repackage goal，mvn clean package 生成 57MB Fat JAR
           java -jar 可直接启动
```

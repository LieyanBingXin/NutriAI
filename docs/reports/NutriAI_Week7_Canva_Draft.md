## 第 3 页 · 核心设计思路

本页标题：为什么不全靠 AI？

三个硬约束：

约束 1：效率
"今天 68kg" → 发 AI 要 1-3 秒 + API 费用
正则解析 < 100ms，零成本
15 种意图覆盖 80% 日常操作

约束 2：准确
自然语言歧义太多
"我家有鸡蛋" → 存冰箱？还是推荐做法？
关键词能精准区分

约束 3：安全
AI 直接操作数据库有注入风险
规则层做安全边界，AI 只负责生成自然语言

我们的方案：规则优先，AI 兜底

用户输入
  ↓
  ├─ 能被规则解析 → 直接执行 → 返回结果（< 100ms）
  │   覆盖 ~80%：体重、冰箱、偏好、查询……
  │
  └─ 规则搞不定 → 带完整上下文发给 AI → 流式自然语言
      覆盖 ~20%："制定减脂计划""分析我的饮食结构"

核心价值：快的事不花钱，难的事才动 AI

## 第 4 页 · 三层处理流水线

本页标题：三层处理流水线（AssistantIntentService）

示例输入："今天吃了 200g 牛肉，刚称 68kg"
568 行核心类，三层递进处理

Layer 0 — 预加载真实数据
取今天真实饮食记录 + 用户画像 + 冰箱快照
→ 避免后续 AI 兜底时瞎编

  ↓

Layer 1 — 查类意图（只读，优先级最高）
"查一下""今天吃了""这周""体重""缺什么"
→ 命中？返回汇总 / 查询结果

  ↓

Layer 2 — 写类意图（自动提取 + 执行）
tryExtractWeight() → "刚称 68kg" ✓
splitIngredients() → "鸡蛋、牛奶"
调对应 Service 直接写入数据库

  ↓

Layer 3 — 分析 + AI 兜底
"缺什么""达标" → 跑营养缺口分析
"推荐""今晚吃什么" → 生成推荐
以上都没命中 → 完整上下文发给 AI，流式返回

## 第 6 页 · 体重提取三层正则

本页标题：关键技术：体重提取三层正则

为什么是三层？

示例："今天吃了 200g 牛肉，刚称 68kg"
问题：两处都有"数字+单位"，正则容易误匹配
期望结果：68kg，不是 200g

Layer 1 — 宽松正则（先捞所有候选项）
匹配模式：数字 + (kg/公斤/斤/两)
- "200g" → g 不在体重单位列表，跳过
- "68kg" → 命中，暂保留 ✓

Layer 2 — 反排除（去掉假阳性）
检查数字前面的语境：
- 前有食材量词（g/克/份/碗/个）→ 这是食物重量，排除
  "200g 牛肉" 前面有单位 → 排除 ✓
- 前有价格词（元/块）→ 排除
- 数值范围验证（20-200 kg 之间）

Layer 3 — 关键词兜底（可信度最高）
前文含体重关键词（体重/称了/刚称）
→ "刚称 68kg" → 确认 ✓

配套：相对日期解析
"今天 68kg" → now
"昨天 68kg" → -1天
"大前天 68kg" → -3天
"3天前 68kg" → -3天

## 第 8 页 · AI 营养提醒区块

本页标题：AI 营养提醒区块（第七周新增）

为什么单独设计？它和其他分区完全不同

对比表：

| 对比维度 | 其他四个分区 | AI 营养提醒 |
|---------|------------|-----------|
| 数据来源 | 用户手动添加 | 系统自动计算 |
| 交互模式 | 点击标签→发送给AI | 纯展示，不可点击 |
| 视觉风格 | 实线边框+纯色背景 | 虚线边框+紫粉渐变 |
| 内容结构 | 标签列表 | 进度条+百分比+AI洞察 |
| 更新机制 | 用户手动增删 | 每次自动刷新 |

营养缺口示例：

近 7 天：12 餐记录
热量 → 60%（偏低）
蛋白质 → 80%（正常）
碳水 → 80%（正常）
脂肪 → 50%（偏低）
膳食纤维 → 20%（严重不足）
钙 → 20%（严重不足）

💡 AI 洞察：最近蔬菜摄入明显偏少，膳食纤维已连续 5 天低于推荐值。建议今天中午加一份深色蔬菜（西兰花/菠菜），晚餐用杂粮代替白米饭。

缺口等级色：
- 严重不足 < 40%（红色）
- 偏低 < 80%（橙色）
- 正常 < 110%（绿色）

无记录时显示："先去记几餐饮食，AI 才能看到缺口"

## 第 11 页 · 核心技术点回顾

本页标题：核心技术点回顾

1. 规则优先，AI 兜底
   15 种意图正则 → 80% 操作 < 100ms 完成
   AI 兜底处理长尾（带完整真实上下文，不瞎编）

2. 体重提取三层反排除
   宽松正则 → 反排除假阳性（食材量/价格）
   → 关键词兜底（"刚称"→确认）

3. 便利贴看板多数据源
   喜好/厌恶/冰箱 → 用户手动管理，点击发送给 AI
   AI 角色标签 → 注入 AI System Prompt，影响回复风格
   AI 营养提醒 → 系统自动计算，纯展示

4. 鉴权威一收敛
   HttpSession → AuthService.getCurrentUserId()
   所有 Controller 使用同一套 Spring Security 鉴权链

5. 营养提醒差异化视觉
   虚线边框 / 紫粉渐变 / 顶部渐变条 / 进度条等级色
   与其他四个分区形成明确的视觉层级

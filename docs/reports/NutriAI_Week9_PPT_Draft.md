## Slide 5 · 移动端：底部导航 + 单列内容

```
设计目标：手机上是"单手可用的记录工具"，不是桌面的缩小版。

  底部导航 5 个主入口：AI 助手 · 我的看板 · 体重 · 食物日记 · 更多
  「更多」= 底部抽屉：画像 · 历史 · 收藏 · 食谱本 · 切换主题 · 退出

关键适配
  · viewport-fit=cover + env(safe-area-inset-bottom)
    → 刘海屏、手势条不遮挡内容
  · 底部导航固定，触控目标 ≥ 34–40px，去掉点按高亮与 300ms 延迟
  · 输入框移动端统一 16px → 避免 iOS 聚焦自动缩放
  · 聊天页 100dvh → 键盘弹出时输入框保持在可视区
  · 移动端隐藏桌面便利贴侧栏与冗余快捷面板
    → 优先保证"对话"和"记录"两条主路径

## Slide 6 · PWA：离线可用 + 可安装

```
不只是"能开网页"，而是"像装了 App 一样"。

  ├── manifest.json       应用名、主题色、192/512 图标（含 maskable）
  ├── Service Worker      应用壳缓存 + 离线回退页
  ├── offline.html        断网时兜底
  └── 安装提示            安卓可"添加到主屏幕"

缓存策略（关键）
  · 静态资源：stale-while-revalidate（先读缓存，后台更新）
  · /api/ 一律不缓存 → 避免饮食/身体等隐私数据落盘
  · 版本号控制：静态资源 ?v=xxx + SW 缓存版本号
    → 改版后强制刷新，避免旧样式残留

价值：安卓端体验接近原生；弱网/断网仍能打开外壳。
```

## Slide 7 · 深色模式

```
实现：全站配色统一收口，切换主题 = 换一套配色。

  浅色：暖纸白底 + 深墨文字

覆盖范围

  · 弹窗 / 图表（Chart.js 颜色随主题切换）/ 看板 rail / toast
```

## Slide 8 · 移动端细节修复：便利贴与输入区

```
这三个是"手机上用起来别扭"的最后一公里，逐一拔掉：

  ① 便利贴抽屉列表横向排列、可左右拖动
     → 改为纵向堆叠、占满宽度、禁止换行，上下滑动浏览

  ② AI 助手标签挂载区可能被输入框挡住
     → 聊天卡改为 flex 纵向结构，挂载区 flex-shrink:0 + z-index 提升，
       输入框 z-index 下沉，层级反转确保挂载区永远在上
     → 挂载区 max-height + 内部滚动，标签多时不撑爆布局

  ③ 便利贴 / 会话标签在手机占满首屏
     → 移动端隐藏桌面便利贴侧栏，保留底部「更多」入口

结构关系：消息区滚动、挂载区 / 输入框固定，三者不互相挤压。
```

## Slide 12 · 部署上线：Cloudflare Tunnel

```
目标：不租云服务器，用自机 + 内网穿透拿到固定公网地址。

  链路
  ┌──────────────────────────────────────────────┐
  │ 用户 → https://nutri-ai.top                    │
  │      → Cloudflare 节点（免费 HTTPS）           │
  │      → cloudflared 隧道（本地客户端）          │
  │      → localhost:8080（Spring Boot）          │
  └──────────────────────────────────────────────┘

  方案要点
  · 域名 nutri-ai.top，NS 托管到 Cloudflare
  · 隧道在 Dashboard 创建，路由 nutri-ai.top → localhost:8080
  · 手动开关（serve-start.bat / serve-stop.bat），不做开机自启

  验证
  · 本地 http://localhost:8080 → 200
  · 公网 https://nutri-ai.top → 200
```
